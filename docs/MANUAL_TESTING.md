# KOSH!RME — manual test checklist

Дата: ______ · OS/version: ______ · Chrome: ______ · Electron: ______ · Экранов: ______

Проверить отдельно на macOS и Windows. Пользуйтесь отдельным тестовым экзаменом и тестовым рабочим столом. Все high screenshots будут видны учителю. Перед тестом закройте личные документы и уведомления, которые не должны попасть на снимок.

## Подготовка

- [ ] `docker compose up` → backend/postgres healthy; `/api/health` отвечает.
- [ ] Admin открывается, неверный teacher key отклоняется, корректный принимается.
- [ ] Создание комнаты показывает четырёхзначный цифровой join code и принимает 1–3 URL.
- [ ] На платформе контеста выполнен вход; разрешённая contest page открывается.
- [ ] Extension загружена из `dist`, после Reload обновлена вкладка Contest.
- [ ] Desktop открыт и виден; второй экземпляр приложения не запускается.
- [ ] Имя + exam code → System Check.
- [ ] После Join pairing code автоматически появляется в clipboard; **Вставить код и подключить** соединяет Extension. При отказе clipboard permission видна подсказка ручного ввода, placeholder не содержит тестовый `AB12CD34`.
- [ ] Повторное открытие/перезапуск соединяется по сохранённому pairing code без повторного ввода.
- [ ] Backend URL и localhost port нигде не показаны ученику и не редактируются.
- [ ] Проверки соединения, Extension и screen permission зелёные.
- [ ] До teacher Start ученик получает только `https://official.contest.yandex.ru/login`; URL контеста не раскрывается.
- [ ] Student consent/Ready открывает страницу логина без monitoring/events/screenshots.
- [ ] Teacher Start открывает/focus назначенного Contest и включает monitoring.
- [ ] Desktop и popup показывают активный monitoring.
- [ ] Учитель видит ONLINE и текущий Last seen.

## Test 1 — разрешённая вкладка

- [ ] Оставаться на контеста 20–30 секунд, переходить по разрешённым подстраницам, писать решение.
- [ ] Expected: нет нарушений; heartbeat обновляется; screenshot не создаётся.
- [ ] В журнал не попадает текст кода, нажатия клавиш, содержимое страниц.
- [ ] Переключаться между всеми тремя разрешёнными URL: нет нарушения и красного экрана.

## Test 2 — другая вкладка

- [ ] Открыть/активировать `https://google.com` в другой вкладке.
- [ ] Expected: `TAB_CHANGED`, high, **+20 за это событие**.
- [ ] Новая вкладка также даёт `NEW_TAB` +10, скрытие Contest может дать `PAGE_HIDDEN` +5. Проверять веса отдельно.
- [ ] Admin мгновенно показывает событие, увеличенные risk/violations и Toast.
- [ ] Desktop выполняет один event capture; в timeline появляется **View screenshot**.
- [ ] Dialog открывает JPEG, видна текущая другая вкладка/экран; правильный ученик и event.
- [ ] Query/fragment адреса не сохранены в `current_url`.
- [ ] Вернуться в Contest: `RETURN_TO_EXAM`, info, risk не уменьшается.

## Test 3 — Alt+Tab / Cmd+Tab и минимизация

- [ ] Оставаясь в Contest, нажать Alt+Tab на Windows или Cmd+Tab на macOS.
- [ ] Expected: `CHROME_FOCUS_LOST`, high, **+25 за событие**, screenshot доступен. В панели: «Окно экзамена потеряло фокус», с пояснением о другом профиле/окне/приложении.
- [ ] На тестовом устройстве переключиться через «Профили» в заранее существующий другой профиль Chrome. Проверить событие потери фокуса, снимок и возврат к экзамену. Имя другого профиля расширение не определяет.
- [ ] На управляемом школьном устройстве с политиками из `prepare-exam-chrome-policy.mjs` проверить запрет пользования профилем с другим аккаунтом и неподписанным профилем. Установка политик требует администратора; ученики работают в обычной учётной записи. Профили с одним разрешённым аккаунтом не различаются, поэтому нужен один подготовленный профиль.
- [ ] Нажать кнопку Lens/Gemini или перевести фокус в адресную/боковую панель Chrome, не меняя активную экзаменационную вкладку.
- [ ] Expected: `BROWSER_UI_ATTEMPT`, high, **+15 за событие**, предупреждение и screenshot доступны.
- [ ] На снимке видно состояние рабочего стола после переключения; другие видимые данные действительно являются частью экрана.
- [ ] Оставить Chrome без фокуса на 20 секунд: нет непрерывных дублей или записи.
- [ ] Вернуться в Chrome/Contest → RETURN_TO_EXAM.
- [ ] После ухода в другое приложение Chrome автоматически возвращается на передний план с Contest (проверить ограничения конкретной ОС).
- [ ] Повторить после минимизации Chrome.
- [ ] Переключение между двумя окнами Chrome не даёт ложного focus loss; запрещённый tab во втором окне всё равно даёт TAB_CHANGED.

## Test 4 — закрытие Desktop Guard

- [ ] Закрыть окно Desktop, оставив Chrome/extension работающими.
- [ ] Expected: `DESKTOP_GUARD_DISCONNECTED`, high, +30; popup Desktop Guard Disconnected (красный).
- [ ] Server не ждёт heartbeat timeout Chrome для этого события.
- [ ] Screenshot у данного события unavailable: закрытый Desktop не может его выполнить.
- [ ] В процессах нет скрытого KOSH!RME после закрытия.
- [ ] Повторный запуск требует нового pairing; пропавшая ранее сессия не теряется в dashboard.

## Test 5 — пропал интернет / связь с backend

- [ ] Разорвать связь ученика с backend (для localhost выключение Wi-Fi не разрывает loopback; используйте LAN или временно остановите backend).
- [ ] Expected при работающем backend на другой машине: спустя >15 секунд от последнего heartbeat → `STUDENT_DISCONNECTED`, +30, OFFLINE.
- [ ] За одно отключение создаётся один timeout event; новых нет каждую секунду.
- [ ] В течение не более 2 минут локальные блокировки и красное предупреждение продолжают работать; события попадают в локальную очередь.
- [ ] После восстановления связи queued events появляются у учителя один раз; risk не удваивается, offline screenshots помечены unavailable.
- [ ] После 2 минут без backend Desktop/extension прекращают monitoring; screenshots offline не создаются.
- [ ] Восстановить сеть → ONLINE, текущее состояние восстановлено, если экзамен ещё активен.
- [ ] Если backend был целиком выключен, notification появится только после его запуска/watchdog; dashboard тоже показывает reconnect.

## Test 6 — finish и отзыв согласия

- [ ] Teacher Finish при активном ученике: Desktop Monitoring stopped, popup STOPPED.
- [ ] Открыть 3 вкладки и переключить приложения после Finish: **ноль новых событий и screenshots**.
- [ ] Попытки POST event и upload для старого event отклоняются backend.
- [ ] Finish во время screenshot: backend не принимает upload после завершения транзакции Finish; клиент отбрасывает полученный кадр при смене состояния.
- [ ] Повторный Start завершённого экзамена отклоняется.
- [ ] В новом экзамене Student Stop monitoring: сбор прекращается, учитель получает событие прекращения, возврат heartbeat не включает сбор без нового Student Start.
- [ ] Отключить сеть, затем Student Stop, затем вернуть сеть: monitoring не возобновляется без согласия.

## Test 6a — пауза, продолжение и удаление

- [ ] Teacher нажимает **Пауза**: monitoring немедленно прекращается у всех, новые события не создаются.
- [ ] Статус готовности учеников сохраняется.
- [ ] Teacher нажимает **Продолжить мониторинг**: monitoring возобновляется без повторного Join.
- [ ] Активную комнату удалить нельзя; после паузы или завершения удаление доступно.
- [ ] Удаление очищает комнату, sessions, events и связанные screenshots.

## Test 7 — permissions и несколько экранов

- [ ] macOS без Screen Recording permission: понятная инструкция, Start недоступен, screenshot не обходится.
- [ ] Разрешить через macOS, перезапустить приложение: System Check Ready.
- [ ] Отозвать permission во время экзамена: следующие screenshots unavailable, без crash/обхода.
- [ ] При двух мониторах JPEG содержит оба монитора; проверить Retina/разные scale factors и вертикальный монитор.
- [ ] JPEG ≤5 MiB, размеры ≤2560×1440, filename UUID, нет постоянной записи.
- [ ] Windows: проверить обычный рабочий стол, UAC/secure desktop отдельно — ограничения ОС не обходятся.

## Test 8 — URL и минимальный сбор

- [ ] Разрешён `/contest/12345/`; `/contest/12345/problems/A/` допустим.
- [ ] `/contest/123456/` не допустим.
- [ ] `contest.yandex.ru.evil.example` не допустим.
- [ ] До Join/Start изменение вкладок не создаёт записей на backend.
- [ ] Нет разрешений history, cookies, microphone, camera, debugger. `clipboardRead` запрашивается только кнопкой автовставки pair-кода; произвольный clipboard не уходит на backend.
- [ ] Правый клик, Menu и Shift+F10 не открывают context menu, создают `GOOGLE_LENS_ATTEMPT`; запрос к `lens.google.com` блокируется dynamic rule.
- [ ] Content script не меняет DOM контеста.
- [ ] Четвёртый разрешённый URL форма/API не принимают.

## Test 8a — языки

- [ ] В dashboard переключить Русский ↔ Қазақша; страницы комнат, учеников и учителей обновляются.
- [ ] В Desktop и Extension отдельно переключить Русский ↔ Қазақша; выбор сохраняется после перезапуска.

## Test 9 — доступ и устойчивость

- [ ] Неавторизованный screenshot GET → 401; чужой student token не может upload к чужому event.
- [ ] Несуществующий filename/path traversal не выдаёт файлы сервера.
- [ ] HTML/PNG под именем `.jpg` не принимаются как JPEG.
- [ ] Неверный pairing code отклоняется; ordinary website Origin не подключается к localhost server.
- [ ] Перезагрузить dashboard: students/timeline восстанавливаются из backend.
- [ ] Перезапустить MV3 service worker во время активной сессии: recovery либо timeout виден учителю.
- [ ] Разорвать admin WebSocket: виден reconnect, после восстановления актуальная таблица.
- [ ] Несколько одинаковых event UUID не увеличивают risk повторно; risk никогда не превышает 100.
- [ ] Быстрые high events: cooldown отображает отсутствие дополнительного screenshot, не создаёт постоянную запись.

## Test 10 — installers

- [ ] macOS `.app` из созданного `.dmg` запускается на целевой архитектуре; permissions привязаны к установленному приложению.
- [ ] Windows NSIS устанавливает и запускает приложение на машине без Node/Python.
- [ ] Проверить Start, violation screenshot, Finish на установленном приложении, а не только в dev.
- [ ] Проверить подпись/notarization перед школьным распространением.
