# KOSH!RME Desktop 0.1.8 для Windows

Для сборки и проверки используйте Windows 10/11 x64 с .NET Framework 4.8 и Node.js x64 22.12 или новее. Распакуйте исходники в отдельную папку. Сценарий установит зависимости по lock-файлу, запустит проверку типов и тесты, соберёт Desktop и расширение Chrome.

## Подписанный установщик

Настройте сертификат подписи кода от доверенного Microsoft удостоверяющего центра. Для сертификата в хранилище Windows задайте `KOSHIRME_WINDOWS_CERT_SHA1`. Для совместимого файлового сертификата electron-builder читает `WIN_CSC_LINK` и `WIN_CSC_KEY_PASSWORD`. Закрытый ключ и пароль храните в хранилище секретов. [Требования Microsoft Smart App Control](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control)

Из корня проекта выполните:

```powershell
.\Build-Windows.cmd
```

Сборка проверяет Authenticode у установщика и всех EXE и DLL в распакованном приложении. Готовый файл называется `apps/student-desktop/release/KOSHIRME-0.1.8-x64.exe`. В GitHub Actions подписанная сборка запускается вручную с параметром `signed` и секретами среды `windows-signing`.

Для внутренней сборки без подписи передайте `-UnsignedTestBuild`. Установщик получит суффикс `-x64-TEST.exe`. Для проверки на компьютерах с включённым Smart App Control используйте подписанный файл.

## Проверка на школьном компьютере

1. Установите подписанный EXE на Windows 11 с включённым Smart App Control под обычной учётной записью. Проверьте запуск из меню «Пуск» и через `koshirme://`.
2. Откройте Коширме до контеста и дождитесь проверки доступа к экрану. Для браузерного подключения требуется Chrome с расширением KOSH!RME 0.3.0 или новее.
3. Откройте отдельный тестовый контест на fizmat.win. Дайте согласие, подтвердите закрытие приложений и убедитесь, что сайт и панель учителя показывают активный мониторинг.
4. Проверьте старт с открытым Блокнотом и несохранённой работой. Сохранение или ручное закрытие должно позволить повторить старт. Ошибка проверки или отказ в доступе должны блокировать готовность.
5. Проверьте снимок при тестовом нарушении, паузу и завершение. Закрытие клиента или потеря проверенной сессии завершают попытку.

Windows-помощник собирается заранее и читает процессы окон через Win32. Журнал `%APPDATA%\KOSH!RME\logs\desktop-checks.log` содержит операцию, стадию, PID, тип исключения, Win32-код и HRESULT, если их вернула ОС. Ошибка доступа к отдельному процессу не отменяет список. Если принадлежность и личность нужного приложения установить не удалось, оно остаётся препятствием для старта.

В 0.1.7 проверка приложений запускала PowerShell с `-File`. В режиме `ConstrainedLanguage` исходный скрипт воспроизводимо останавливается на создании `UTF8Encoding` с ошибкой `CannotCreateTypeConstrainedLanguage`. Динамический `Add-Type` с Win32-обёрткой в этом режиме также запрещён. Оба шага выполнялись до перечисления окон, а Desktop заменял исходную ошибку общим сообщением. Успешный запуск `Get-Process` и WMI отдельно от приложения не проверяет эти шаги. Для подтверждения той же причины на конкретном школьном ПК нужен его исходный журнал PowerShell.
